# AIGC 出图工作台（独立实现 · 演示）

> 一个面向「设计团队商品图生产」的出图工作台：把**凭感觉的活**拆成「**可复用配方 + 可验收标准**」。
>
> ⚠️ 本项目是**独立实现**，用于演示一套出图工作流的链路设计与数据模型，**不包含任何前司资产、客户数据或内部素材**。演示数据（项目 / 人员 / 截图）全部为虚构。

---

## 它解决什么问题

设计团队真实出图时，通常是这样：

- 每个人用不同模型、各写一套 Prompt，出图规格与命名不统一
- 复杂流程只存在于「节点图」里 —— 不写 Prompt、不懂节点的人走不完
- 每上一个新款都要从零重做一遍，经验沉淀不下来

这个工作台的判断是：**先把「凭经验」变成「照流程走」，才谈得上提效**。工具越灵活，各人做法越散。

## 两个关键设计（本项目最值得看的部分）

### 1. 两条互不依赖的支线

```
参考图 → 反推提示词
   ├── 支线 A：模特基础照   （不含款式）
   └── 支线 B：场景初版     （不含款式）
              ↓
        最终组合：注入款式（款 × 形象 × 场景）
```

**为什么这样拆**：两条支线都不含「款式」这个变量，所以它们可以各自复用；款式只在最后组合阶段延迟注入 —— 避免款式变更级联影响上游产出，使支线可独立迭代。

### 2. 视觉配方（Recipe）不含款式 → 跨款复用

出图经验沉淀为一条「配方」，字段包括人物 / 场景 / 产品 / 动作四段提示词与生成参数，但**不含款式字段**。

所以：一次沉淀，N 个款通用。把「每款从零重做」转成「复用配方 + 注入款式」。

设计上要权衡的是 **字段抽象度 vs 跨款泛化边界**：字段过细则难以泛化，过粗则丢失视觉一致性。

## 架构

```
浏览器（单页前端，六视图）
        │  REST (JSON)
        ▼
aigc_workbench.py        本地 HTTP 服务 + 路由 + 数据层（JSON 文件存储）
        │
        ▼
aigc_gen_tool.py         生成引擎：多端点调用 / 视觉理解 / QC 校验 / 降级兜底
        │
        ├── presets.yaml             图类型 → 模型 / 参考图数 / 输出尺寸（换模型只改这里）
        └── data/*.json              projects / assets / recipes / performance / rounds / batch / admin
```

**模型接入是可插拔的**：图类型与模型的映射外置在 `presets.yaml` 与后台管理里，更换模型只需替换端点与密钥，不触及链路代码。

## 六个视图

| 视图 | 作用 |
|---|---|
| 出图 | 单次生产：参考图 → 提示词 → 支线生成 → 组合 |
| 批量生成 | 多款并发跑同一配方，带审核队列 |
| 文生图 / 图生图 | 自由出图通道 |
| 素材库 | 素材按类型归档（ref / base_person / base_scene / final …） |
| 操作日志 | 人员 / 时间 / 张数 / 提示词 / 模型，用于迭代优先级判断 |
| 后台管理 | 模型与端点配置、成员与配额、环境健康 |

## 快速开始

```bash
# 1) 配置密钥
cp .env.example .env
#   编辑 .env，填入你自己的 API Key

# 2) 启动
python aigc_workbench.py
#   默认 http://localhost:8080

# 3) 想看界面但没有密钥？
python aigc_workbench.py --mock
#   联调模式：不调用真实模型，用占位图与假数据跑通全流程
```

依赖：Python 3.10+，`requests` / `pillow` / `opencv-python`（生成引擎用于 QC 与图像处理）。

重新生成演示种子数据：

```bash
python _demo_seed.py
```

## 关于仓库里的数据

- `data/projects.json`、`recipes.json`、`performance.json`、`admin.json` 是**虚构的种子数据**，用于演示界面
- `data/assets.json`、`rounds.json`、`batch.json` 已清空 —— **图片素材不随仓库分发**
- 想看到完整效果：配置好自己的 key 后跑一遍出图，或直接用 `--mock` 模式

## 边界

- 这是**演示与结构参考**，不是生产系统：无鉴权、无并发控制、无数据库
- QC 校验是几何 / 色差 / 清晰度的启发式规则，不是训练出来的判别模型
- 真实生产需要：权限与审计、任务队列、对象存储、失败重试与告警
